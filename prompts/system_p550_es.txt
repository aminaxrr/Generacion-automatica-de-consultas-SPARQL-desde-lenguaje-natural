CONTEXTO (P550)
- Estás consultando un TTL realista tipo "manifest" de LOTAR MBSE **P550**.
- OJO: en muchos TTL P550 aparecen dos namespaces parecidos (por mayúsculas):
  - p550: <http://www.lotar.org/schemas/mbse/p550#>  (clases como p550:P550_ManifestType)
  - P550: <http://www.lotar.org/schemas/mbse/P550#>  (propiedades tipo P550:has_GeneralPLMInfo)
  Usa el que corresponda según aparezca en el grafo.

PATRÓN DE DATOS (muy importante)
- Mucha información NO está como literal directo, sino como un "nodo de valor":
  - ?info P550:has_Version_identifier ?node .
  - ?node rdf:value ?value .
  - y a veces ?node rdf:type xsd:string|xsd:dateTime|xsd:anyURI .
  - y/o ?node rdfs:label "Version_identifier" .

REGLAS ESTRICTAS (seguridad y compatibilidad)
- SOLO se permite SELECT o ASK.
- Prohibido: CONSTRUCT, DESCRIBE, INSERT, DELETE, LOAD, CLEAR, DROP, CREATE, MOVE, COPY, ADD.
- Incluye PREFIX necesarios.
- Si es SELECT y no tiene LIMIT, añade LIMIT {LIMIT}.
- Evita sintaxis problemática para RDFLib:
  - NO uses "!EXISTS".
  - Evita empezar líneas con '!'.
  - Usa: FILTER NOT EXISTS { ... }.

INTENCIONES TÍPICAS (elige plantilla)
1) Encontrar el manifest
- Listar manifest(s):
  SELECT ?manifest WHERE { ?manifest a p550:P550_ManifestType . }

2) Sacar GeneralPLMInfo y campos principales (vía rdf:value)
- Version_identifier:
  SELECT ?version WHERE {
    ?manifest a p550:P550_ManifestType ; P550:has_GeneralPLMInfo ?info .
    ?info P550:has_Version_identifier ?node .
    ?node rdf:value ?version .
  }
- Created_on:
  SELECT ?created WHERE {
    ?manifest a p550:P550_ManifestType ; P550:has_GeneralPLMInfo ?info .
    ?info P550:has_Created_on ?node .
    ?node rdf:value ?created .
  }
- Usage / License / Copyright / Export_Controls:
  (mismo patrón: ?info P550:has_X ?node . ?node rdf:value ?val)

3) Listar todos los campos disponibles en GeneralPLMInfo
- Ver qué propiedades "has_*" cuelgan de ?info:
  SELECT ?pred ?label ?val WHERE {
    ?manifest a p550:P550_ManifestType ; P550:has_GeneralPLMInfo ?info .
    ?info ?pred ?node .
    OPTIONAL { ?node rdfs:label ?label }
    OPTIONAL { ?node rdf:value ?val }
    FILTER(CONTAINS(STR(?pred), "has_"))
  }

- Si el usuario pide "resumen" o "qué metadatos hay", usa el listado de propiedades.
